# Migrating from v0.7 to v0.8

What a caller of v0.7.1 changes to build against v0.8.0, and what behaves
differently without failing to compile. The
[API stability](../../README.md#api-stability) policy allows these breaks
before v1.0.0; from v1.0.0 on, CI refuses an incompatible Go API change
within a major version (see
[RELEASE.md](../../RELEASE.md#compatibility-checks)).

## Every package

| v0.7.1 | v0.8.0 |
|--------|--------|
| `ProfileDiff.IsEqual()` | The `Equal` field |
| `FormatDiff(diff)` | `diff.String()` |
| `apparmor.FormatProfile`, `landlock.FormatProfile` | `profile.String()`; `seccomp.FormatProfile` stays |
| `MaxPathLen` 4096 | 4095, the longest path the kernel opens; a path of 4096 bytes is now refused with `ErrPathTooLong` |

- **Error messages** name a failure by the JSON path of the member, as in
  `syscalls[1].args[0].index: 9: syscall arg index out of range (max 5)`.
  Match the sentinels with `errors.Is` rather than the text.
- **Merges report every bad input.** `Intersect` and `Union` check every
  input and join one `InputError` per failing input, in input order, where
  they stopped at the first. `errors.As` still finds the first, and
  `spm.Problems` lists them all.
- **`Diff` of a nil profile** returns an `InputError` naming it.
- **Strict decoding** refuses a document that is not a JSON object
  (`ErrNotAnObject`), and `DecodeArtifact` decodes and validates an
  artifact in one call.
- **New shared sentinels**: `ErrArtifactTooLarge`, matched by every
  `ErrTooMany*`; `ErrBudgetExceeded`, returned by `apparmor.Intersect`,
  `apparmor.ValidateBaseline` and both landlock merges past their work
  budgets; `ErrInexactBaseline`, from the new `ValidateBaseline` of
  seccomp and apparmor; and `ErrInvalidOptions`, matched by every error
  of a `seccomp.Options` or `landlock.Options` that names no node to
  check for.
- **Check every baseline with the new `ValidateBaseline`** of its package
  at config load (for landlock, `Options.ValidateBaseline` with the node's
  ABI version), which refuses what would otherwise fail every merge.

## seccomp

The functions that took a native architecture are methods of `Options`,
which comes from a constructor. The zero `Options` and a `ForArch`
architecture the package does not know fail every method with an error
matching `ErrInvalidOptions`, which is `spm.ErrInvalidOptions`; the
unknown architecture matches `ErrUnknownArch` as well.

| v0.7.1 | v0.8.0 |
|--------|--------|
| `IntersectForArch(arch, ...)`, `UnionForArch`, `DiffForArch`, `ValidateArtifactForArch`, `ValidateStrictForArch` | `seccomp.ForArch(arch).Intersect(...)` and the other methods |
| The empty `Arch` passed to them | `seccomp.ForAnyArch()`, which reads the node as possibly any architecture rather than as none, and whose `Intersect` refuses a list mixing the two byte orders (`ErrMixedByteOrder`) |
| `IntersectSyscalls`, `UnionSyscalls`, `DiffSyscalls` | A profile with a strict default action, merged with `Intersect`, `Union` or `Diff` |
| `MoreRestrictive`, `LessRestrictive` | Removed; the merges rank actions themselves |
| `ProfileDiff.DefaultAction`, `DefaultErrnoRet`, `ListenerPath`, `ListenerMetadata` of type `*ActionDiff`, `*UintPtrDiff`, `*StringDiff` | `*ValueDiff[T]` with `Left` and `Right` |
| `ErrTooManyEntries` (entries for one syscall) | `ErrTooManyEntriesPerSyscall`. `ErrTooManyEntries` still compiles but now means too many entries in the profile, past `MaxArtifactEntries` |
| `ErrTooManyClauses`, `MaxArtifactClausesPerSyscall` | `ErrTooManyRulesPerSyscall`, `MaxArtifactRulesPerSyscall` |
| `ErrTooManyProfileClauses`, `MaxArtifactClauses` | `ErrTooManyRules`, `MaxArtifactRules` |
| `ErrTooManyNames` | `ErrTooManyNamesPerEntry` |
| `SyscallEntry{Name: n, Action: a, ErrnoRet: e, Args: args}` | `SyscallEntry{Name: n, SyscallDetail: SyscallDetail{Action: a, ErrnoRet: e, Args: args}}`: the entry embeds the detail, so reading `entry.Action` and the JSON are unchanged |

- **`Validate` refuses runtime-spec fields it does not read**
  (`ErrUnsupportedSpecField`) and a `listenerPath` or `listenerMetadata`
  that is not valid UTF-8 (`ErrInvalidUTF8Listener`).
- **`Validate`, and so the merges and `ValidateBaseline`, refuse a
  `listenerMetadata` without a `listenerPath`**
  (`ErrListenerMetadataWithoutPath`), which the runtime-spec forbids and
  `Union` used to ignore.
- **`Intersect` and `Union` refuse inputs naming different listeners**
  (`ErrConflictingListener`).
- **`UnmarshalStrict` requires** `names` and `action` in a syscall entry
  and `index` and `op` in an argument condition, and refuses a null entry
  or condition (`ErrMissingField`).
- **`Intersect` refuses an input listing an architecture of the other byte
  order** (`ErrMixedByteOrder`), and `Union` may refuse a result in which
  libseccomp would lose the rules of an architecture (`ErrLostRules`).
- **`ValidateArtifact` and `ValidateStrict`, and so `DecodeArtifact`,
  refuse, rather than settle, an architecture of another byte order than
  the node's** (or, for `ForAnyArch()`, a list mixing both;
  `ErrMixedByteOrder`) **and rules libseccomp would lose**
  (`ErrLostRules`).
- **`Intersect` may drop architectures** where libseccomp would lose the
  rules of one: x32 where it pairs with x86_64, x86_64 where x32 is native,
  the affected architecture where it is not native, and otherwise the
  listed architectures on which the offending syscall applies. Where it
  can drop none it returns `ErrLostRules`.
- **`Union` of two inputs no longer depends on their order** where two
  rules with one result spell the same filter, such as `a0 < 1` and
  `a0 == 0`: it keeps the same one whichever input comes first. With three
  or more inputs, which merge pairwise, the order can still change how
  tight a result of either merge is, never its guarantee.
- **A complement rewrite no longer emits the rule equal to the
  default**: where a merge splits a syscall into a one-condition rule
  and its complement, it leaves out the half whose result is the
  default, which matched only calls the default answers the same way.
  Results compare equal under `Diff`, but stored merge results change.
- **`Diff`, `Intersect(p)` and `Union(p)` drop a rule another rule with
  the same result covers** where the rules of a syscall form a safe shape,
  such as `a0 == 8` next to `a0 < 16`, as every merge of two or more
  inputs does, so `Diff` reports no change where only such a rule differs
  and `ValidateBaseline` accepts a baseline holding one. A syscall of more
  than 512 conditional rules is not pruned, in a merge or in `Diff`, so
  `Diff` may report such a rule there as a change.
- **`switch_endian` and `sys_debug_setcontext` count as one syscall**
  where libseccomp gives both one number: in a filter covering an
  architecture that keeps rules on syscalls it lacks, such as x86_64, or
  covering ppc, ppc64 or ppc64le on a node lacking both.
  `ValidateArtifact` and `ValidateStrict` refuse conflicting rules on the
  two (`ErrConflictingEntries`), which libseccomp refuses with `EEXIST`
  or keeps only one of, and count the two as one syscall for the
  per-syscall limits. On a node lacking both, the merges and `Diff` read
  them as one syscall and a result names both. On a PowerPC node or with
  `ForAnyArch()` the merges give both the same rules where a result's
  rules would conflict in such a filter, and `ValidateBaseline` refuses a
  baseline whose own rules on the two conflict so (`ErrInexactBaseline`).
- **Write a result with `seccomp.Marshal`**, which keeps an empty
  `"flags": []` that `json.Marshal` drops (see
  [Extra steps after Intersect](../integration.md#extra-steps-after-intersect)).
- **`Diff` reports a rule's errno above 16 bits as written**, as it does
  the default's: `~read:SCMP_ACT_ERRNO(errno:99999)->...` rather than the
  34463 a runtime loads, which the profile never names, where every entry
  of the syscall with that action and loaded value, in both profiles,
  writes the same value; otherwise it shows the loaded one on both sides.
  It still compares the loaded values.
- **New**: `ValidateBaseline`, which also diffs the baseline against its
  intersection with a profile allowing every call, so that it reports the
  wide values any merge settles, `DecodeArtifact`, `Marshal`, `Clone`,
  `FormatSyscall`, `ForHost()`, the `Options` of the node the program runs
  on, which the plain functions use, and `Options.String`, which spells
  the constructor the options come from.

## apparmor

| v0.7.1 | v0.8.0 |
|--------|--------|
| `StringSliceDiff`, `BoolPtrDiff` | `SliceDiff[T]`, `ValueDiff[T]` |
| `NetworkDiff.AllowRaw`, `AllowTCP`, `AllowUDP` of type `*BoolPtrDiff`, with `*bool` sides | `*ValueDiff[bool]`, with `bool` sides: read `diff.Left` rather than `*diff.Left`. The JSON of each value is unchanged, `{"left":false,"right":true}` |
| `ProfileDiff.Executables`, `Libraries` | `ProfileDiff.Executable`, an `*ExecutableDiff`, following the fields of `Profile` |
| `ProfileDiff.Capabilities` of type `*StringSliceDiff` | `*CapabilityDiff` |
| `FilesystemDiff.ReadOnly`, `WriteOnly`, `ReadWrite` | `ReadOnlyPaths`, `WriteOnlyPaths`, `ReadWritePaths` |
| `NetworkDiff.AllowTCP`, `AllowUDP` | `NetworkDiff.Protocols.AllowTCP`, `AllowUDP` |
| `ErrDuplicatePath` | `ErrDuplicatePathAcrossCategories`, a path in two filesystem categories |
| `ErrDuplicatePathInCategory`, `ErrDuplicateExecutablePath` | `ErrDuplicatePathInList`, a path twice within one list: a filesystem category, `AllowedExecutables` or `AllowedLibraries` |
| `ErrDotComponent` | `spm.ErrDotComponent`, shared with landlock; `apparmor.ErrDotComponent` still names it |
| `ErrNulInPath` | `spm.ErrNulInPath`, shared with landlock; `apparmor.ErrNulInPath` still names it |

The JSON of a diff follows the fields of `Profile` too:

| v0.7.1 | v0.8.0 |
|--------|--------|
| `"executables"`, `"libraries"` | `"executable"` with `"allowedExecutables"` and `"allowedLibraries"` |
| `"capabilities"` | `"capability"` with `"allowedCapabilities"` |
| `"readOnly"`, `"writeOnly"`, `"readWrite"` | `"readOnlyPaths"`, `"writeOnlyPaths"`, `"readWritePaths"` |
| `"network"` with `"allowTcp"`, `"allowUdp"` | `"network"` with `"allowedProtocols"` holding `"allowTcp"`, `"allowUdp"` |

- **Capability names come back in lower case** (`chown`), the spelling
  apparmor_parser accepts, where v0.7.1 upper-cased them, and
  `ValidateArtifact`, `ValidateStrict` and `ValidateBaseline` refuse a name
  with the `cap_` prefix in any case, such as `CAP_CHOWN`
  (`ErrInvalidCapabilityName`).
- **`Validate`, and with it every merge, refuses a relative path**
  (`ErrRelativePath`), including one whose escapes spell the first `/`,
  such as `\x2fetc/passwd`.
- **`Intersect` can fail** with `ErrBudgetExceeded` where the inputs
  together are too large to intersect exactly. The pass that restores the
  grants of literal paths charges its budget for every input it narrows a
  literal against, so an intersection of many profiles listing many
  literals can fall back to the folded result, which may grant less on
  those literals and never more.
- **`Intersect` of two or more profiles can keep more literal paths**: the
  result grants every literal path an input lists what every input grants
  it, through its own entry or its patterns, so within the budgets what it
  permits there no longer depends on the input order, and a literal can
  move to another list of a diff. A profile intersected alone or with
  itself is unchanged.
- **`Validate`, and with it `ValidateArtifact`, refuses a path listed
  twice in `AllowedExecutables` or `AllowedLibraries`**
  (`ErrDuplicatePathInList`), as it refuses one listed twice in a
  filesystem category, where only `ValidateStrict` did. The merges still
  fold such a path into one entry.
- **`ValidateArtifact` and `ValidateStrict` refuse paths v0.7.1
  accepted**: a pattern apparmor_parser loads as something else, such as
  `/a/[\^x]` (`ErrInvalidGlob`), and an unescaped character that does not
  render, such as ESC, U+2028 or U+3164 (`ErrUnquotablePath`); the escaped
  form, such as `\x1b`, is accepted.
- **An empty capability list formats as nothing**: `CapabilityRules{}`
  formats as the empty string, as the other empty sections do, rather than
  `caps:none`, and `Profile.String` leaves it out, as it leaves out a nil
  one, which denies the same. A capability named `none` is no longer
  quoted.
- **`MaxArtifactPatternBytes` counts only the paths `IsGlobPattern`
  reports**, so a literal path escaping a character, such as
  `/home/user/My\ Documents`, no longer counts.
- **New**: `ValidateBaseline`, which also refuses capability names
  apparmor_parser does not load, the paths `ValidateArtifact` refuses for
  what they load as, such as `/a/[\^x]` or a `..` component, and glob
  patterns longer in total than `2*MaxArtifactPatternBytes`
  (`ErrBudgetExceeded`), `QuotePath` (render every path through it; it
  refuses a pattern apparmor_parser rejects), `DecodeArtifact` and
  `Profile.Clone`.

## landlock

| v0.7.1 | v0.8.0 |
|--------|--------|
| `ValidateForABI(profile, abi)` | `landlock.Options{ABI: abi}.Validate(profile)`, and its `ValidateArtifact`, `ValidateStrict` and `DecodeArtifact` |
| `DowngradeToABI(profile, abi)` | `landlock.Options{ABI: abi}.Downgrade(profile)` |
| `RequiredABIVersion(p) ABIVersion` | `RequiredABIVersion(p) (ABIVersion, error)`, which validates `p` |
| `Intersect(inputs...)` followed by `LoweredRulePaths(result, inputs...) []string` | `IntersectLowered(inputs...) (*Profile, []LoweredPath, error)`, which merges and reports the lowered paths of that merge in one call. Open each `Path` beneath its `Ancestor` with openat2 and `RESOLVE_BENEATH`, `RESOLVE_NO_SYMLINKS` and `RESOLVE_NO_XDEV`, or with `RESOLVE_IN_ROOT` alone where `InRoot` is set; `Input` is the input whose rule is on `Ancestor`. A bad input is an `InputError`, as from `Intersect`. `LoweredRulePaths` also took a `Union` result, for which v0.7.1 documented its answer as informational only, since a union grants what any input grants; `IntersectLowered` merges by intersection only |
| `ErrParentPath` | `ErrDotComponent`, which is `spm.ErrDotComponent`, shared with apparmor; the message still reads `path contains a ".." component` |
| `RightsDiff` | `SliceDiff[T]` |
| `ErrInvalidPath` | `ErrNulInPath`, shared through `spm` |

- **New `ValidateBaseline` and `Options.ValidateBaseline`**: the checks of
  `ValidateArtifact` but `MaxArtifactRules`, and through `Options` the
  node's ABI version, so that a trailing slash, a rule granting an
  unhandled right and the like fail at config load.
- **`Validate`, and with it every merge, `IntersectLowered` and
  `RequiredABIVersion`, refuses a relative path** (`ErrRelativePath`), `./`
  included, which `Validate` reported as `ErrEmptyPath`. The merges compare
  paths as text, while the kernel resolves a relative path against the
  working directory of the process loading the ruleset, so an intersection
  could keep a grant an input denies there.
- **`Options` with a version below `ABIV1`** fails every method with an
  error matching `ErrInvalidOptions`, which is `spm.ErrInvalidOptions`, as
  well as `ErrUnknownABIVersion`.
- **`Union` results can change** so that they keep their guarantee after
  `Options.Downgrade` to any version: where an input handles only rights
  newer than `ABIV2` the result leaves `refer` unlisted, and where a rule
  grants `refer` as well it stops handling filesystem rights, which
  permits more.
- **The merges validate their inputs** and refuse inputs past a work
  budget with `ErrBudgetExceeded`. `Union` also counts the moves it settles
  beneath each grant of `refer`, so it refuses more inputs where they grant
  `refer` on a directory they share: two inputs of `MaxArtifactRules` rules
  on the deepest paths rather than three. [Limits](../integration.md#limits)
  gives the figures.
- **`Intersect` stops listing `refer`** where no rule of the result grants
  it and the result handles another right `ABIV1` knows, since the kernel
  denies `refer` there all the same. An input handling `read_file` and
  `refer` with a rule granting `read_file` on `/`, intersected with one
  handling `read_file`, gives a result handling `read_file` alone, so
  `RequiredABIVersion` of the result is `ABIV1` rather than `ABIV2`.
- **`UnmarshalStrict` refuses a path rule without a path**, a null one
  included (`ErrMissingField`, naming `pathRules[0].path`), which v0.7.1
  decoded and the validators then refused with `ErrEmptyPath`.
- **`LatestABIVersion` is `ABIV12`**, and the validators reject a trailing
  slash (`ErrTrailingSlash`) and a path that is not valid UTF-8
  (`ErrInvalidUTF8Path`) in an artifact.
- **The JSON of a changed rule leaves out** an empty `"left"` or
  `"right"`.
- **New**: `DecodeArtifact`, `Profile.Clone`, `ABIVersion.String`,
  `Options.String`, which spells the options as Go source writes them, such
  as `Options{ABI: ABIV4}`, and the listings `FSAccessRights`,
  `NetAccessRights` and `ScopeRights`.

## spm

| v0.7.1 | v0.8.0 |
|--------|--------|
| `spm.Diff`, the interface `{ IsEqual() bool }` | Removed, with no replacement: the diff types share no method for the verdict, so read the `Equal` field of the concrete `ProfileDiff` |

`spm.Problems` lists the failures of an error, and `spm.ValueDiff[T]` is
the new shape of a changed value, which `seccomp.ValueDiff` and
`apparmor.ValueDiff` name. The new sentinels are listed under
[Every package](#every-package), with `spm.ErrDotComponent`, which is
`apparmor.ErrDotComponent` and `landlock.ErrDotComponent`, and
`spm.ErrNulInPath`, which is `apparmor.ErrNulInPath` and
`landlock.ErrNulInPath`.

## The spm command

- **`spm validate --artifact` and `spm merge --validate artifact` fail on
  an unknown member** and exit 1, where v0.7.1 warned and exited 0 (a
  misspelled member already failed). A CI gate running either on such a
  file now fails; remove the member, or validate in the default mode,
  which still warns.
- `spm validate` writes an array for several inputs and for an array of
  any length, on stdin or in a file, and an object for one profile, each
  profile as it was read, or as it decoded where readers would decode it
  differently, such as for a member spelled in another case. It no longer
  re-indents: a compact profile stays compact and unknown members are
  kept. To normalize one profile, run `spm merge --strategy union
  one.json`.
- Every input that cannot be read, decoded or validated is reported, each
  line naming the input, and the run exits 1; a usage error exits 2 and is
  followed by a hint at the help of the command.
- `spm diff --format json` writes the diff JSON of each package, so it
  follows the renames above.
- `--format human` writes one setting, rule or change per line, rather
  than the one line the library's `String` writes for a log.
- A flag given twice with different values, such as
  `--strategy union --strategy intersect`, is a usage error rather than a
  run of the last one.
- A repeated JSON member is an error in every mode, an input of no known
  profile type is refused, and `--arch` names the node for `merge` and
  `validate`. [cli.md](../cli.md) describes each.
- An input whose type differs from `--type` or cannot be detected, such as
  `spm validate --type seccomp apparmor_baseline.json` or a `{}`, exits 1
  like any other failing input, where v0.7.1 exited 2.
- `--type ""` and `--output ""` are usage errors (exit 2), where v0.7.1
  read them as left out.
- An `--output` that is a symbolic link or a directory, such as
  `/dev/stdout`, is a usage error (exit 2) found before any input is read,
  where v0.7.1 did the work and then exited 1.
- `spm help merge extra` is a usage error (exit 2), where v0.7.1 ignored
  the extra argument and exited 0.
- Flags may follow the file arguments, so `spm validate a.json --strict`
  checks `a.json` strictly where it was a usage error. A file whose name
  starts with `-` and comes after another file argument is read as a flag
  now; put it after `--`.
- Errors of the `flag` package name a flag with one dash, as in
  `flag provided but not defined: -typo`, however it was given.
- `spm validate` takes `--validate <mode>[,<mode>]` as `merge` and `diff`
  do, with the extra mode `baseline`; `--artifact`, `--strict` and
  `--baseline` stay as short forms, and none of them may be combined with
  `--validate` or with each other. `--arch` with only `default` modes
  reports `--arch only applies to the strict, artifact and baseline
  checks`. `baseline` decodes strictly, as `artifact` does, so an unknown
  or misspelled member fails it.
- A Landlock `spm merge --strategy intersect` whose result holds lowered
  rule paths, except one whose ancestor is `/` in a result granting no
  `refer`, exits 1 where an input is checked with `artifact` or `strict`,
  and warns otherwise:
  load such inputs as separate Landlock layers, or merge with
  `landlock.IntersectLowered` (see [cli.md](../cli.md#merge)).
- `spm merge --abi` checks the result for that version too, so a union of
  ABI 1 inputs that handles `refer` alone exits 1 for `--abi 1`.
- The note `auto-detected profile type` is written only once every input
  decoded as that type, so a run with an input that does not decode no
  longer writes it.
- `--output` naming a file the caller owns and can write, in a directory
  that takes no new file, such as a read-only one, writes the file in
  place rather than failing. On Linux a replaced file keeps its `user.`
  and `trusted.` extended attributes, and its SELinux label where SELinux
  labels new files; a label the process cannot carry over is kept by
  writing such a file in place, and fails the run otherwise.
- `--format human` is not a stable interface: it changed completely since
  v0.7.1, and an empty AppArmor capability list no longer prints
  `caps:none`. Scripts read `--format json`.
